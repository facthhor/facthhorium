## Repeatability and prefill capacity

With the v0.2.1 card's 512-token prefill capacity, the merged program was not repeatable. Each round sent a 9,261-token prompt, then a 36,694-token prompt, so the second prompt was prefilled again from a 512-token cached prefix. Five greedy rounds produced five different outputs. The outputs diverged at near-tie tokens, which points to small run-to-run numerical drift in prefill. Fully cached prompts and short prompts repeated exactly. The same sequence was exact on the v0.2.1 program with XL weights (3/3) and on untouched upstream (8/8), whose card uses a 4,096-token prefill capacity. Upstream's MoE bucket change (one GEMM width per expert) did not fix the 512-token case.

At a 4,096-token prefill capacity, the merged program repeats exactly with the drafter off (3/3) and at depth 3 (3/3). It matches upstream's greedy output, and depth 3 matches depth 0 for all 64 generated tokens at 36,694 input tokens. Prefill of the 36,694-token prompt takes 22 s, compared with about 40 s at 512. Peak GTT during these runs was 20.8 GiB. The card now uses 4,096. Probe scripts: `logs/v03/probe2.py` (history sequence) and `probe.py` (cached repeats).

## Preview gate

The preview ships the merged program with an FP16 KV cache, draft depth 3, a 4,096-token prefill capacity and a 131,072-token context. The global-KV Q8 work continues on a development branch. On this package, the quality sweep at temperature 1, top-k 0, top-p 1 and maximum effort passed:

- 14/14 math problems.
- 5/5 code problems.
- 4/4 vision checks, including 16 images.
- 1/1 tool call.
- All retrieval facts at 9,261, 36,694, 73,000 and 122,593 input tokens (52/52).

A repeated greedy request at 36,694 tokens produced identical output. A context ramp from 32,775 to 131,079 tokens peaked at 24.7 GiB GTT with at least 3.2 GiB of system memory available.

## Release gate (v0.3.0)

v0.3.0 is the preview program with two fixes. The relay's run header now names the XL target and the drafter. The tool parser cuts a generated call body at the end of its first balanced JSON object or array, so stray bytes after the call no longer fail the turn with "trailing JSON input". `program/llm.loom` and `program/storage.loom` are byte-identical to the preview's.

A verbatim-copy test checks long-range recall. The context is Rust source the model cannot have memorized. Each request quotes one unique line and asks for the six lines that follow it, with greedy decoding at draft depth 3. Ten probes at 50,084 input tokens and ten at 95,746 returned all 120 lines exactly. The global-KV Q8 builds stay in development: on the same test at depth 3, Q8 values alone copied 108 of 120 lines and Q8 keys and values copied 92 of 120.

On the release build, a chat request and a tool call (`read_file` with a `path` argument) completed through the relay, which served a 131,072-token context.
